## STALL REPORT (the binding part)

**Recommendation: revise before autonomous implementation.** The backend is implementable, but the stated config, pricing and acceptance contracts conflict. In particular, the proposed partial-price verdict becomes a falsely complete dollar total in the existing quote publisher. The $200 wallet is explicitly not enforced as one ceiling; do not describe this deliverable as providing one.

Execution order below is SDK smoke → backend/config → quote → acceptance. No taskplan for this PRD exists in this worktree; phase names refer to the inlined PRD. Source paths are relative to the repository root. The initial placeholder was committed before investigation as `14c9d4f`.

1. **PHASE / MODULE: config-to-backend request construction — explicit sampling parameters.**
   - **DECISION I CANNOT MAKE:** The request rule says “Sampling parameters are omitted unless the seat's `params` explicitly carries one.” Q4 prescribes `params: {temperature: 0}`. AC12 instead says “unless its config sets one explicitly.” Which representation is authoritative after config resolution?
   - **WHY IT STALLS ME:** `CouncilConfig._seat` removes temperature from model params and puts it in `SeatSpec.temperature`, defaulting to zero (`src/kbutillib/domains/ai/council/config.py:981`). `as_llm_request` copies that field separately from extras (`src/kbutillib/domains/ai/llm/types.py:329`). A backend checking only `req.params` drops explicitly configured temperature. Reading `req.temperature` sends the default zero on every call. Those are observably different wrong implementations. A local execution with `params={'temperature': 0.3}` produced `seat.temperature=0.3` and `seat.extra={}`.
   - **RECOMMENDED RESOLUTION:** Add: “For anthropic only, `_seat` sets `temperature=None` when model params omit temperature, preserves an explicit temperature in `SeatSpec.temperature`, and the backend sends a non-None `LLMRequest.temperature`; direct LLMRequest callers opt in through `params['temperature']`, which overrides that field, while the inherited default field value alone does not opt in. Other providers retain their current defaults.” This also requires an explicitness rule for direct requests; implement it using pydantic field-set metadata or a dedicated adapter, and test omitted and explicitly supplied zero separately. If direct callers should use only params, say so and normalize council requests into that representation instead. The PRD must choose one contract.

2. **PHASE / MODULE: config validation — bucket identity and unknown models.**
   - **DECISION I CANNOT MAKE:** Q3 mandates “one alias per Anthropic RATE-LIMIT BUCKET,” but the specified validation only rejects different buckets on the same account. Q7 additionally says the bucket “should be scoped to the credential's organisation/workspace.” Q10 permits new models through configuration without specifying unknown-model behavior or a required organisation identity.
   - **WHY IT STALLS ME:** Two aliases for the same bucket and organisation with different arbitrary account strings pass the named checks and create two independent pacers, reproducing the over-subscription this validation promises to prevent. Conversely, two organisations legitimately have independent pools for the same model. Environment-variable names do not establish organisation identity: different keys may share a quota. I cannot infer whether to refuse, accept, or group these configurations. Unknown canonical models also cannot be classified merely by allowing the table to be overridden. `EndpointConfig` has account and credential names but no organisation identity (`src/kbutillib/domains/ai/council/config.py:587`); grouping uses the account directly (`src/kbutillib/domains/ai/council/engine/worker.py:673`).
   - **RECOMMENDED RESOLUTION:** Add: “Each anthropic endpoint declares a non-secret `options.quota_scope` identifying the operator-asserted organisation/workspace quota; require exactly one account value for each `(quota_scope, resolved_bucket)` and prohibit one account from representing multiple such pairs. Unknown canonical models require an explicit entry in a top-level `anthropic_rate_limit_buckets` mapping, merged over defaults; reject missing entries with the canonical identity named. Operators are responsible for truthful quota_scope values; validation cannot discover them from API keys.” Define empty/unreferenced endpoints as permitted without model-bucket validation until a model is attached. The precise mapping syntax is an implementation choice Q10 expressly delegates; the identity and unknown-value policy are not.

3. **PHASE / MODULE: config and answer reuse — incompatible namespace acceptance.**
   - **DECISION I CANNOT MAKE:** AC7 demands a resolved reuse namespace “distinct from that of any other endpoint.” The implementation instead defaults all Anthropic aliases to `https://api.anthropic.com`, relying on the existing namespace derivation.
   - **WHY IT STALLS ME:** `default_reuse_namespace` intentionally permits aliases of one deployment to share answers and uses normalized base URL plus revision, ignoring account and served model (`src/kbutillib/domains/ai/council/types.py:210`). Locally invoking it for haiku and opus accounts returned `https://api.anthropic.com#` for both. Canonical model is separately part of answer identity. I must either fail AC7 or change established reuse semantics by inventing alias/account separation.
   - **RECOMMENDED RESOLUTION:** Replace AC7 with: “The namespace is non-empty and derived from normalized base_url and deployment_revision; aliases of the same deployment may share it, while distinct canonical models remain separate in the existing reuse key. This PRD does not require namespace uniqueness per endpoint alias.”

4. **PHASE / MODULE: pricing eligibility — size-tiered models.**
   - **DECISION I CANNOT MAKE:** Q13.2 says rates “should refuse — or at minimum loudly warn on — a rate declared for a model known to be size-tiered,” while Out of Scope excludes Haiku 5.5 “as a priced seat.” Q10 permits newly configured models. Refusal, warning plus pricing, and remaining unpriced are different contracts.
   - **WHY IT STALLS ME:** There is no pricing-capability field in `ModelConfig` and rates are arbitrary strings (`src/kbutillib/domains/ai/council/config.py:686`, `:809`). A gateway fallback could price a tiered model even if a composite model rate was rejected. I cannot implement the “exactly-priced” claim while choosing warning-and-linear-pricing, nor identify a new model's pricing capabilities solely from its bucket. The PRD explicitly lacks the model ID for its named exception.
   - **RECOMMENDED RESOLUTION:** Add: “V1 supports only flat input/output pricing. Allow `pricing_mode: flat|unsupported` on model config, with the documented shipped defaults flat and unknown models defaulting to unsupported; an unsupported model remains unpriced regardless of composite or gateway fallback rates, and a composite rate explicitly targeting it is rejected. Haiku 5.5 must be configured unsupported until tiered pricing is implemented.” This is an explicit safety policy; alternatively remove the promised tiered-model guard and clearly limit exactness to operator-verified flat rates.

5. **PHASE / MODULE: quote publication — partial sums and the preserved gateway shape.**
   - **DECISION I CANNOT MAKE:** The PRD says the change is “confined to one function,” keeps the gateway's “existing shape,” adds `priced: "partial"`, and requires “A partial sum must never be presented as a total.” It does not define the aggregate `rate`, `rate_provenance`, or currency for differently priced contributing models.
   - **WHY IT STALLS ME:** `Quote.to_dict` uses truthiness to select priced gateways and computes `dollars_complete` from the complementary set (`src/kbutillib/domains/ai/council/quote.py:1125`). The non-empty string `"partial"` therefore contributes its subtotal while making the headline claim completeness. The CLI has the same boolean assumption (`src/kbutillib/interfaces/cli/council.py:337`). This is the exact silent mispricing the PRD forbids. Also, `RateConfig.currency` is a free string (`src/kbutillib/domains/ai/council/config.py:771`): summing differently denominated rates is undefined, and a single legacy rate pair cannot represent three rates.
   - **RECOMMENDED RESOLUTION:** Add: “Expand scope to `Quote.to_dict` and the quote CLI: only `priced is True` means fully priced; partial and unpriced gateways set headline dollars_complete=false and appear in unpriced_gateways. Headline dollars values are explicitly labelled known priced subtotals whenever incomplete, and the CLI names unpriced canonical models. Multi-rate gateways keep `rate=null` and `rate_provenance=null`, with contributing rate/provenance records under by_model; require all priced rates in a quote to use one currency and reject mixed currencies. Sum unrounded model costs before rounding gateway totals.” Test the published quote and CLI, not only `_price_gateways`.

6. **PHASE / MODULE: quote calibration — wallet versus rate bucket.**
   - **DECISION I CANNOT MAKE:** User story 16 requires “one row per wallet rather than one per model.” The implementation says `_balance_delta_block` remains “keyed on gateway,” because “there is one balance per wallet.” Q3 has just redefined those gateway keys as independent rate-limit buckets sharing one bill.
   - **WHY IT STALLS ME:** `_balance_delta_block` generates a balance row for every gateway (`src/kbutillib/domains/ai/council/quote.py:1665`). Three accounts/buckets on the same API wallet produce three rows asking for the same console balance. Copying that wallet delta into each row attributes the entire bill three times and corrupts per-bucket calibration. There is no wallet identifier separate from account in the specified config.
   - **RECOMMENDED RESOLUTION:** Add: “Introduce a non-secret `billing_wallet` identifier for anthropic endpoints, required and independent of rate-limit account. Keep pricing and pacing grouped by account, but group balance-delta rows by billing_wallet, aggregate all member gateway token totals, and emit member gateway names. A wallet balance delta does not independently identify each member model's effective input/output rate; do not generate per-model calibration rates from that single observation.” Alternatively explicitly drop story 16 and disable calibration for shared-wallet buckets. Leaving this function unchanged cannot satisfy the story.

7. **PHASE / MODULE: live acceptance and completion gate.**
   - **DECISION I CANNOT MAKE:** Testing Decisions says “AC1–AC4 are executed against a live call with a real key” and “No stub can satisfy them.” AC4 requires an endpoint “whose provider reports no usage object.” The prompt assumes no ability to ask the author anything.
   - **WHY IT STALLS ME:** This process has no nonempty `ANTHROPIC_API_KEY`, and no installed SDK. Installing the SDK closes the dependency gap but cannot create a credential. Even with a key, the PRD supplies no live, safe method to make the real provider omit usage. A normal response does not demonstrate the no-usage halt, while a transport fixture is explicitly disallowed. AC6 also requires a live response. I cannot honestly declare these criteria met overnight from the repo alone. This is a verification blocker, not a reason to stop ordinary coding or to invent API results.
   - **RECOMMENDED RESOLUTION:** Add: “Implementation and offline verification may finish without provider credentials, but delivery remains live-acceptance-pending until an operator supplies the named credential, model, isolated store and explicit spending cap for AC1–AC3 and AC6. AC4 is an engine integration test using an injected provider response with usage omitted; it is excluded from the live-only requirement. Record pending live criteria without claiming acceptance.” If overnight full acceptance is mandatory, provision those inputs before dispatch; prose cannot substitute for a key.

No additional binding blocker was found for installing/smoking the actual SDK, built-in registration, lazy imports, typed status mapping, text-block parsing, truncation, credential resolution, optional-dependency markers, or leaving the store schema and batching table unchanged. The missing `llm/__init__.py` entry in “Modules to modify” is an obvious edit implied by built-in registration, not an author decision. SDK signature discovery is expressly delegated to phase 1 and is not itself a stall.

## FREE CRITIQUE (non-binding)

- **The wallet promise is larger than the delivered mechanism.** Story 9 says “stop by itself when the $200 is spent,” but Out of Scope explicitly excludes a cross-endpoint wallet ceiling. Respect that scope; do not quietly build new budget machinery. Document that correctness depends on a provider-enforced console limit. Existing `_enforce_budget` checks a token threshold after a call, returns immediately without a configured budget, and only halts the named endpoint (`src/kbutillib/domains/ai/council/engine/worker.py:3084`). AC4 must configure a budget. Tokens are not dollars, especially across model/input/output mixes; concurrent in-flight calls can overshoot a soft token ceiling.

- **RPM pacing is not token pacing.** Q8 itself says ITPM/OTPM bind on council prompts. A correct RPM value plus concurrency 4 does not guarantee compliance with either token allowance. Record-and-halt is a deliberate scope choice, but avoid promising reliable throughput from it. A follow-on should measure prompt and output distributions before choosing a conservative requests/minute value.

- **Extras can defeat the stated invariants.** The prose permits provider extras but also says thinking and output format are not requested and schema_enforced is always false. Clearly distinguish defaults from prohibited capabilities. If an operator passes `output_config.format`, reporting false becomes inaccurate; tools and streaming can also change the response shape. Guard reserved model/messages/max_tokens keys, forbid stream/tools in this lane, and ensure recursive cache_control detection covers merged request/endpoint extra_body before sending. These are tractable backend validation choices; do not confuse excluding caching by default with refusing all ways to enable it.

- **Header visibility needs end-to-end verification.** A backend attribute is process-local and ephemeral. In queue workers it will not automatically reach the submitter. Debug logging may be disabled. Define and test a practical way AC6 obtains the observation and reports its comparison, including rate-limit error responses and late-arriving observations. Never feed it into pacing under this scope.

- **Use the actual pinned dependency, not latest-main examples.** On this research run the [official SDK manifest](https://raw.githubusercontent.com/anthropics/anthropic-sdk-python/main/pyproject.toml) reports version 2.3.0, Python >=3.10 and httpx2. That does not invalidate the requested 1.x pin; it means phase 1 must inspect the installed 1.x artifact rather than treating today's main branch as its API. The [published package metadata](https://pypi.org/pypi/anthropic/json) also supplies an Opus 5.5 example ID, so the claim that its ID is unobtainable is no longer a useful reason to guess one. No SDK was installed for this review and no SDK call surface was validated here.

- **A no-socket SDK smoke proves client compatibility, not provider truth.** It can exercise real serialization, response-model parsing and raw-response headers with a mock transport. Such output is observed SDK behavior, but the response envelope remains a fixture. Label provenance accordingly. Keep live usage/store verification as a separate gate.

- **Credential-only readiness is intentionally weak.** A present key does not establish valid authentication or model access. Preserve the free preflight contract but make its limited claim explicit. Missing-key factory behavior should also allow the stated refused preflight without accidental SDK constructor failure preventing that result.

- **Do not perturb existing providers to fix Anthropic.** Prefer an Anthropic-local thinking-tag cleaner unless tests demonstrate a shared-helper change preserves old behavior. Wire proxy and per-request timeout through the selected SDK client, with a transport injection that genuinely exercises serialization. Disable SDK retries for models enumeration too if the wrapper's one-attempt policy is intended to cover diagnostics.
