## STALL REPORT (the binding part)

Recommendation: do not hand this bundle to an unattended implementer yet. The existing architecture is usable, but the bundle leaves biological evidence precedence, canonicalization, ranker arithmetic, and evaluation semantics undecided. These are observable behavior, not implementation preferences. The ordered list below follows dependency order (artifact → resolvers → scorer → orchestration → evaluation → acceptance). Quoted text refers to the supplied PRD; proposed resolutions are concrete policy choices for the author to adopt, not claims that those choices were already authorized.

1. **PHASE / MODULE: Resolve the specification before implementation.**
   - **DECISION I CANNOT MAKE:** Fullprompt says `combine="precedence"` is “the default”; humanprompt says “Both routes are combined by reciprocal rank fusion (k=60)” and calls “Q4 (RRF weights)” an open item. Neither document declares precedence over the other.
   - **WHY IT STALLS ME:** The same default call has two different required rankings. Choosing the human summary silently reinstates the behavior the detailed design explicitly rejects.
   - **RECOMMENDED RESOLUTION:** Add: “fullprompt.md is authoritative when these documents conflict; precedence is the default, RRF is opt-in, and humanprompt.md's default-RRF and open-Q4 statements are superseded.”

2. **PHASE / MODULE: Corpus builder, graph-derived fields.**
   - **DECISION I CANNOT MAKE:** The required schema contains `"depth", "height", "leaf"` without defining them. GO terms can have multiple `is_a` parents; depth can mean shortest or longest root distance. The PRD also retains obsolete nodes without specifying their graph attributes.
   - **WHY IT STALLS ME:** A valid parser does not determine these values. Different choices produce incompatible artifacts and future stratified evaluations even from the identical OBO.
   - **RECOMMENDED RESOLUTION:** Add: “Compute graph attributes on active terms and asserted is_a edges only: depth is minimum distance from any parentless active root (root=0), height is maximum distance to any active leaf (leaf=0), and leaf means no active children; obsolete terms have null depth/height and leaf=false. Reject cycles and dangling active-parent references.”

3. **PHASE / MODULE: Canonical GO resolution shared by corpus, ec2go, and provided GO.**
   - **DECISION I CANNOT MAKE:** User Story 6 requires “obsolete GO terms excluded from results by default and merged terms (`alt_id`) resolved to their current accession.” Q6 relies on obsolete records carrying `replaced_by`, but gives no policy for zero/multiple replacements, replacement chains, `consider`, unknown accessions, or identifier-route hits outside the corpus. “Excluded from ranking” is narrower than “excluded from results.”
   - **WHY IT STALLS ME:** Passing through every curated/provided ID can emit dead terms. Treating `consider` as a replacement or choosing one of several replacements fabricates a biological assertion. Dropping every obsolete ID can lose a uniquely resolvable mapping.
   - **RECOMMENDED RESOLUTION:** Add: “All routes canonicalize GO IDs before deduplication: resolve alt_ids to their owner, follow a unique replaced_by chain to an active term, never use consider as an automatic replacement, and omit unresolved/ambiguous/unknown IDs with per-result identifier diagnostics; cycles or conflicting alias ownership are corpus errors. No route emits an obsolete term.” Define the separate missing-corpus exception in item 4.

4. **PHASE / MODULE: Independent route degradation and provenance.**
   - **DECISION I CANNOT MAKE:** “Corpus path unset or unreadable” disables lexical while `function_to_go` “still serves the ec2go route.” Yet every result requires `go_release: str`, `corpus_sha256: str`, and candidates require `name` and `namespace`. ec2go supplies a GO label but not the GO namespace or the missing OBO's hash. There is no specified ec2go config key or source-version/hash field. “Every result ... names the GO release it was produced against” also has no answer when the independently staged files disagree.
   - **WHY IT STALLS ME:** I cannot return the stated schema truthfully without the corpus. Inventing its release/hash misrepresents reproducibility; requiring the corpus violates independent degradation. Hashing only the OBO cannot reproduce an identifier result after ec2go changes.
   - **RECOMMENDED RESOLUTION:** Add: “Use ontology_mapping.ec2go_path for the independently staged, read-only ec2go file; never fetch it during inference. go_release and corpus_sha256 are null without a corpus; corpus_sha256 means the source OBO byte SHA-256, and add corpus_artifact_sha256 plus ec2go_sha256 and ec2go_release to results/status. An ec2go-only candidate uses its mapping-file label and namespace=null, with canonicalization_status='unverified'; provided GO without a corpus uses name=go_id and namespace=null with the same status. With a corpus, corpus metadata is authoritative; report source release disagreement explicitly.” This makes the exception to item 3 explicit rather than pretending the missing corpus can validate IDs.

5. **PHASE / MODULE: BM25 synonym-scope arithmetic.**
   - **DECISION I CANNOT MAKE:** “The base synonym weight of 2.0 is multiplied by scope” does not say where multiplication occurs relative to term-frequency saturation and length normalization. The readable Type 1 implementation concatenates all synonyms into one field, then computes shared document length and document frequency: `/scratch/vsetlur/function-ontology-mapping-program/studies/01_function_to_go/pipelines/type_1/field_aware_bm25_char/source.py:53`, `:69`, `:84`.
   - **WHY IT STALLS ME:** A gram occurring in both exact and broad synonyms has no single scope in the existing field. Weighting fractional TF before saturation, saturating each synonym separately, or scoring separate scope buckets produces different rankings and different duplicate-synonym effects. The one exact-versus-broad test cannot distinguish these implementations.
   - **RECOMMENDED RESOLUTION:** Add: “Keep Type 1's name, definition, document-frequency and total-length calculations; concatenate synonyms into four scope-specific fields and apply BM25 saturation independently per scope field using the shared document-length normalization, then multiply each field contribution by 2.0 times its scope multiplier. Count a gram once per document for IDF across all fields, and preserve synonym order within scope.” Note that this deliberately differs from flat Type 1 even when all multipliers equal 1; correct Q11's contrary claim accordingly.

6. **PHASE / MODULE: Public function signature, structured-record schema, route selection.**
   - **DECISION I CANNOT MAKE:** The headline has `routes=None`; later text adds `records` with dicts that “may carry ec, interpro, pfam and go identifiers” and says the abstention list is “extensible by the caller.” It defines neither record value types nor the extension parameter. “When present these feed the identifier route directly rather than being re-extracted from text” does not distinguish an empty record, a record containing only Pfam, or an explicitly empty EC list. It also never says whether `routes=["ec2go"]` suppresses provided GO.
   - **WHY IT STALLS ME:** A string-versus-list assumption can iterate identifiers character by character; replacing text extraction whenever any record exists loses valid inline ECs. Different route interpretations violate the curated-only caller's expectations and become incompatible API contracts over all transports.
   - **RECOMMENDED RESOLUTION:** Add: “Expose function_to_go(descriptions, ids=None, top_k=10, routes=None, *, combine='precedence', records=None, abstention_terms=None); records is a length-aligned list of dicts whose four supported values are list[str], absent keys mean empty lists, and unknown keys or wrong types raise ValueError. A nonempty structured ec list replaces inline extraction; otherwise extract inline ECs. routes=None enables ec2go and lexical, routes=[] enables neither, unknown route names raise ValueError, and provided GO is processed independently of routes. abstention_terms adds exact normalized strings to the defaults. Reject mismatched lengths and nonpositive/noninteger top_k before loading data.” IDs/order can follow the existing precedent at `src/kbutillib/domains/genome/ontomap_utils.py:243`.

7. **PHASE / MODULE: Abstention versus identifier evidence.**
   - **DECISION I CANNOT MAKE:** Abstention says an uninformative description returns “no candidates”; structured GO is “passed through ... ahead of everything else.” For `description="hypothetical protein"` plus `records={"go": ["GO:0004022"]}` these cannot both hold. The same issue applies to a valid structured EC paired with placeholder text.
   - **WHY IT STALLS ME:** Running abstention first destroys stronger upstream evidence; running identifiers first violates the unconditional zero-candidate placeholder rule. This affects common annotation output, not an exotic invalid input.
   - **RECOMMENDED RESOLUTION:** Add: “Placeholder detection disables lexical scoring only; if provided GO or ec2go yields candidates, return those with abstained=false. Return abstained=true and reason='uninformative_description' only when placeholder text has no resolved identifier evidence. Match normalized whole strings; DUF-only means the entire normalized text matches duf[0-9]+. Empty/whitespace-only descriptions use the same policy.”

8. **PHASE / MODULE: Provided GO versus fusion and duplicate attribution.**
   - **DECISION I CANNOT MAKE:** Provided GO is “ahead of everything else,” but RRF is defined as a sum “over routes” and only names two routes. Each candidate carries singular `route`, while duplicates retain `per_route_rank` and `per_route_score`. A GO ID can be provided, ec2go-derived, and lexical simultaneously.
   - **WHY IT STALLS ME:** Including provided IDs in ordinary RRF can demote them, violating User Story 22. Excluding them without defining fill/deduplication can reduce output size or lose evidence. The `route` field can misleadingly call a mixed-evidence RRF candidate exclusively lexical or curated.
   - **RECOMMENDED RESOLUTION:** Add: “Under both combine modes, canonical provided GO IDs form an ascending-ID prefix, count toward top_k, and do not participate in RRF. Combine ec2go and lexical to fill the remaining slots, suppress prefix duplicates, and retain all participating per-route evidence. route is 'provided' for prefix terms, otherwise 'ec2go' or 'lexical' for single-source terms and 'combined' for multi-source terms; precedence score for overlaps is the ec2go score.”

9. **PHASE / MODULE: Fusion input depth and lexical fill.**
   - **DECISION I CANNOT MAKE:** RRF specifies the formula but not how many candidates each route contributes before fusion. `top_k` bounds returned results, not explicitly the internal rankings. The motivating example uses a candidate at lexical rank 100 despite default `top_k=10`.
   - **WHY IT STALLS ME:** Cutting each route to top_k before RRF discards lower-rank corroboration and changes the winner. Taking only top_k lexical results before precedence deduplication can also underfill the response when curated terms overlap that prefix.
   - **RECOMMENDED RESOLUTION:** Add: “top_k applies only after canonicalization, full-route ranking, combination and deduplication; RRF consumes the complete active lexical ranking and all resolved ec2go IDs, and precedence scans lexical until filled or exhausted. Preserve Type 1's zero-score candidates in its complete ranking.” An optimized implementation may compute equivalent output without materializing every intermediate entry.

10. **PHASE / MODULE: Public result schema and confidence signal.**
    - **DECISION I CANNOT MAKE:** The return-shape example omits the required `abstained` and reason, and has no field to satisfy “interpro and pfam are accepted and recorded.” It requires `top1_margin` as rank-1 score minus rank-2 score even though precedence scores are explicitly incomparable; Gotchas nevertheless says “top1_margin is the signal to use.”
    - **WHY IT STALLS ME:** I must invent transport-visible fields and their locations. An ec2go 1.0 above lexical 20.0 yields margin -19.0 for the intended preferred answer; presenting that as confidence contradicts the design's own score warning.
    - **RECOMMENDED RESOLUTION:** Add: “FunctionToGoResult serializes to the documented dict with additional abstained: bool, abstention_reason: str|null, input_identifiers: {ec,interpro,pfam,go: list[str]}, and identifier_diagnostics: list[dict]. GoCandidate is a serializable dataclass and to_terms() belongs to FunctionToGoResult. Repeat the result's top1_margin on each candidate; set it to null unless the top two scores share a scale (same sole route under precedence, or both non-prefix RRF candidates). Under single-route rrf, scores are 1/(60+rank).” Remove the claim that cross-route margins are confidence signals. Existing `Term` accepts this evidence shape at `src/kbutillib/domains/genome/annotation/annotator_utils.py:67`.

11. **PHASE / MODULE: Evaluation cohort and gold eligibility.**
    - **DECISION I CANNOT MAKE:** The harness takes `(gold_path, queries_path, limit=None)` and promises a “held-out gold set,” but supplies no split selection, text-field choice, join rule, or eligibility rule. The actual readable query file contains both `raw_text` and `normalized_text` and `source_split_metadata="train"`; gold rows key by `entity_id`, not `query_id`, and carry resolution flags. The source scorer selects the test partition from a separate split file (`.../type_1/field_aware_bm25_char/source.py:154`, `:241`).
    - **WHY IT STALLS ME:** Joining by query_id yields no gold. Evaluating the whole file reports training examples as held-out quality. Treating unresolved/obsolete annotations as positives distorts accuracy; truncating before selecting the test cohort changes which queries are measured.
    - **RECOMMENDED RESOLUTION:** Add: “Add split_path and evaluation_split='test' to evaluate_function_to_go; join queries to gold on entity_id, use raw_text, and select query_ids via split-membership.tsv rather than source_split_metadata. Gold positives are the deduplicated canonical_go_id values whose resolution_status is active and in_full_active is true, excluding unknown_or_unresolved rows; reject positives absent from the loaded active corpus. Exclude and count queries with no eligible gold; apply limit in query-file order after filtering and split selection. Duplicate query_ids or missing split membership raise ValueError.” This matches the current active-only positive-state constant in `.../pipelines/support/go_schemas.py:12`.

12. **PHASE / MODULE: Evaluation metric definitions and executable interface.**
    - **DECISION I CANNOT MAKE:** “per route and fused” does not identify which combine modes, MRR cutoff, prediction set for hierarchy metrics, averaging, or handling of abstentions. Recall@20 cannot be measured from the default ten returned candidates. “Writes nothing outside a caller-named output path” names an argument absent from the signature. User Story 24 requires coverage/abstention without a denominator definition.
    - **WHY IT STALLS ME:** Several reasonable evaluators return materially different quality numbers. Restricting the denominator to answered queries inflates quality; using ten candidates silently caps recall@20. Using every ranked GO term for hierarchy precision makes the metric meaningless.
    - **RECOMMENDED RESOLUTION:** Add: “Report ec2go-only, lexical-only, precedence and RRF runs on the identical eligible cohort; report macro means of per-query top1 membership accuracy, full-ranking reciprocal rank, recall@1/5/10/20, and self-inclusive asserted-is_a closure precision/recall of top1 versus all eligible gold IDs, including roots. Empty predictions contribute zero to these metrics; coverage is nonempty predictions divided by eligible queries and abstention_rate is explicit abstentions divided by eligible queries. Record degraded-route failures separately and fail evaluation if a requested route is unavailable. Add output_path=None: return a JSON-compatible report, and write that same report only when explicitly supplied. Include cohort counts, input hashes, mapper provenance and metric definitions.” The reusable formulas are readable in `.../pipelines/support/go_metrics.py:20` and `:37`; eligibility precedent is `.../pipelines/support/go_validate.py:25`. Those sources clarify possibilities but do not choose this PRD's reporting policy.

The facade/registration and no-injection acceptance phases have no additional blocking ambiguity once the above contract is fixed. Existing lazy-property composition and registry discovery determine the mechanics (`src/kbutillib/toolkit.py:415`; `src/kbutillib/core/capability.py:364`). A temporary operator-style config and staged fixture files can exercise `KBUtilLib()` with no constructor injection; it need not edit a real operator's config.

## FREE CRITIQUE (non-binding)

- **Verification scope:** Inspected the checked-out repo and the readable external Type 1 scorer, sampled real gold/query records, and inspected shared metric/validation functions. This was source investigation, not an implementation or benchmark: no production code/config/schema was changed and no mapper tests were run because the proposed mapper does not exist. No web verification was necessary for these internal contract contradictions. The supplied fullprompt/humanprompt are the reviewed specification; they are not checked-in files at the requested PRD directory, so citations to them use section names and quotations rather than invented file line numbers. External source paths are evidence available now, not proposed runtime dependencies.
- **The Type 1 research gap is closed on this host.** Its source is readable: normalization is ASCII `[a-z0-9]+`, lowercase, tokens joined by spaces, then one space padded at both ends; grams are counted with multiplicity, query TF multiplies contributions, K1=1.2/B=0.75, and IDF is `log(1+(N-df+0.5)/(df+0.5))` (`.../type_1/field_aware_bm25_char/source.py:30`, `:47`, `:88`, `:93`). This is not a current stall. The fallback still omits IDF, padding and query-TF rules, so record these details in the PRD to make it portable when scratch disappears.
- **Do not claim equal multipliers reproduce Type 1 without proving it.** Scope-specific BM25 saturation does not algebraically equal saturation of concatenated synonym TF. Add hand-computable cases with the same gram in multiple scopes and repeated synonyms; a name-versus-definition ordering test alone does not validate the port.
- **Zero-score retrieval is dangerous but already implied by porting Type 1.** The source deliberately appends every zero-score candidate (`.../source.py:93`). Placeholder abstention catches a list, not arbitrary gibberish, punctuation or unrelated English. With no positive overlap the output can simply be the lowest GO IDs. Document that behavior, report its rate, and consider an explicit no-overlap abstention in a subsequent decision; do not quietly invent a threshold during implementation.
- **No measured quality gate is explicitly out of scope, so its absence is not a stall.** It remains a release risk: an evaluation tool can prove the system is poor after it has already been built. The scope multipliers and precedence are hypotheses, not established biological accuracy. A meaningful frozen evaluation report should accompany eventual review.
- **The curated route's evaluation may share the gold's evidence source.** The sampled gold provenance includes `project="UniProtKB-EC"`; query provenance also embeds gold evidence. This does not prove leakage, but warrants source-stratified reporting and a strict prohibition on passing query provenance's gold GO IDs as structured input. Otherwise provided-GO preservation can turn an evaluation into answer replay.
- **The RRF counterexample establishes possibility, not prevalence.** The repeated claim that reversal is “the expected shape” is unsupported without corpus measurements. Keep the characterization test and precedence default, but do not advertise the anecdote as comparative accuracy evidence.
- **Caching needs an operational contract.** The PRD says once per instance; operators must know rebuilding a file will not refresh an existing instance automatically. Include restart/recreate guidance. Load lazily: `register_all` accesses facade properties and skips objects whose constructors raise (`src/kbutillib/core/capability.py:416`), so eager corpus validation could make all three diagnostic capabilities vanish precisely when the data is corrupt.
- **A source OBO hash is not the corpus artifact hash.** Changed builder logic or altered JSONL can change scores while preserving the source hash. Item 4 recommends recording both, plus ec2go's hash; also record ranker configuration/scope constants and code version in evaluation output.
- **Partial corruption deserves a test.** The copied dictionary parser skips malformed rows and only fails when all rows are unusable (`src/kbutillib/domains/genome/annotation/ontology_dictionary.py:99`). A truncated JSONL with one surviving term can pass that minimum. Validate header term_count against loaded unique terms and detect duplicate GO IDs; test missing provenance headers and partially malformed files. These are worthwhile integrity improvements, not grounds to invent a new failure contract silently.
- **Stdlib-only is a dependency policy, not a performance result.** The source index retains documents, TF counters and posting tuples (`.../source.py:58`), and ranks the entire universe per query (`:100`). Measure full-corpus startup RSS and a multi-thousand-query batch before calling this interactive. No latency target is stated, so inventing one would be inappropriate.
- **The fixture size estimate is implausible.** “~20 real GO terms ... a few hundred bytes” does not fit the required rich schema. Commit a small, attributed, deliberately selected fixture and keep generated bulk data ignored; the estimate should not constrain correctness.
- **The taskplan is not actually supplied.** References to Task 1–7 help infer sequence but are not acceptance definitions. The current body is enough to identify the architectural work; any separately enforced taskplan must be included and reconciled before an unattended run.

Confidence: high on the identified contract conflicts and the current readability of the relevant source/data. A revised authoritative signature, canonicalization/fusion policy, and hand-calculated evaluation example would raise confidence that an autonomous implementation can finish without inventing behavior.
