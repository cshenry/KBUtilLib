## summary
Gave the shared clearinghouse parity fixtures and the OP3 parity script an
`entity_type` field, matching the `entity_type` column the previous task in
this plan added to the `result` table's declared schema. Every one of the 13
fixture rows in `clearinghouse_parity_fixture.py` (across all six
`ParityCase`s, including the 3 rows generated by `DUPLICATE_COLLAPSE`'s
generator expression) now carries `"entity_type": "protein"` — pinned to the
same value for every row, since `_standardize_protein` and
`_standardize_gene_dna` are the same standardizer and only the pair
`(entity_hash, entity_type)` is a unique identity. The module docstring's
slot-key description was restated from the old three-part
`(entity_hash, result_type, source)` key to the four-part
`(entity_hash, entity_type, result_type, source)` key, with a one-line note
on why (shared standardizer). The `ParityCase.rows` attribute docstring was
also updated to list `entity_type` among the row's keyword shape, since it
directly documents the shape I changed. In
`scripts/clearinghouse_parity_check.py`, `_RESULT_COLUMNS` (the column-order
list used to shape rows read back from the Spark query in
`_query_current_state`) gained `"entity_type"` immediately after
`"entity_hash"`, matching its position in the table's declared columns.
