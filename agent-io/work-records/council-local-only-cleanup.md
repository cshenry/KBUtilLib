form of self-hosted model management, and KBase identity from the council.

## 4. The v1 → v2 migration

`SqliteStore.migrate()` dispatches on the stored version: `0` → `init_schema()`,
`2` → `add_missing_columns()` only, `1` → `_migrate_v1_to_v2()` then
`add_missing_columns()`, anything else → `SchemaVersionMismatch`.

`_migrate_v1_to_v2()` runs **one transaction** containing, in order:

1. `_merge_endpoint_state()` — every row re-keyed onto `STORE_IDENTITY`
   (`"local"`). Per endpoint: `epoch_tokens` and `lifetime_tokens` **summed**
   across historical user labels; the **highest** `budget_epoch` kept (a lower
   one would resurrect a budget already reset); **every halt kept** — one halt
   keeps its message verbatim, several are combined as
   `[<label>] <message>; [<label>] <message>`, sorted by label so the result
   is deterministic.
2. `DROP TABLE IF EXISTS` for each of `schema.REMOVED_IN_V2`. `IF EXISTS`
   because a store from one of the intermediate builds may lack some.
3. The version stamp replaced with 2.

Every job, item, call, attempt, workers and query_types row is untouched. A
second migrate is a no-op (it sees version 2). `db check` reports 2.

`CouncilUtils.db_migrate()` wraps it: `ExecutionLock.acquire("migrate")` for
the duration (refusing, not waiting, if a daemon/run/evaluate holds it), and a
`shutil.copy2` of the store file plus its `-wal`/`-shm` siblings to
`council.sqlite.bak-<UTC timestamp>` before anything is altered. The report
gains `backup`.

## 5. The network-filesystem guard

In `store/sqlite.py`, immediately after the existing Dropbox scan in
`_resolve_sqlite_url()`:

- `refuse_network_filesystem(path, filesystem_type=...)` — platform-neutral:
  the refused set, the override, and finding the directory to ask about.
- `filesystem_type_of(path)` — **the whole injection seam**, one function over
  one existing directory. Linux: longest matching mount point in
  `/proc/self/mounts`. macOS: `stat -f %T`.
- `nearest_existing_ancestor(path)` — the store file and often its directory do
  not exist yet, so the question goes to the closest ancestor that does.
- Refused: `nfs nfs4 cifs smbfs smb2 smb3 afpfs webdav fuse.sshfs sshfs 9p
  lustre gpfs beegfs ceph fuse.ceph`.
- `KBU_COUNCIL_ALLOW_NETWORK_FS=1` — exactly `1`, not any truthy value —
  overrides. The Dropbox refusal is checked first and is **not** overridable.
- An undeterminable type is **allowed with a logged warning**.

**Deliberate deviation from the task text, stated:** the task offered "statfs
`f_fstypename` via ctypes, **or** `stat -f %T`" for macOS. I took `stat -f %T`
only. Reading `f_fstypename` through ctypes means hard-coding its byte offset
inside `struct statfs`, whose preceding fields vary by architecture and SDK;
I cannot test macOS from h100, and a wrong offset returns plausible-looking
rubbish rather than nothing — which would admit a network mount or refuse a
good local disk. `stat -f %T` *is* that field, is the sanctioned way to ask for
it from outside C, and fails honestly. The reasoning is in the function's own
docstring. **The macOS branch is therefore inferred, not verified: it has not
been executed on macOS.** The Linux branch is verified on this host (it reports
`xfs` for `/home/chenry/.kbutillib`).

## 6. Queue identity (round 3)

- `claim_calls` has **no** `jobs.submitted_by` filter: it claims every due
  pending call of every non-cancelled, non-paused, non-tombstoned job in the
  store. `submitted_by` is a provenance label, so filtering on it would strand
  the whole queue the moment somebody edited config `user`.
- `endpoint_state` is keyed on `STORE_IDENTITY = "local"`, in both the store
  methods and `select_claimable`'s halt subquery.
- **Two further places had to follow, beyond the task's list**, or the round-3
  property would not actually hold:
  - `_blockers()`'s `no_daemon` now consults **every** live worker, not the
    job's label's. Scoping it by the label would tell a user to start a worker
    while one was already draining their calls.
  - `CouncilWorker._scope_jobs()` lists every job in the store. Scoping the
    idle check by the label while the claim is unscoped would report "nothing
    left to do" with claimable calls still in the queue.
- The `user` parameter is off every claim and endpoint-state call site; a
  deprecated, ignored `user=None` keyword remains on each.

### dev 1597 — `test_the_exact_argv` on macOS

Folded in. `tests/domains/ai/council/test_cli_backends.py` gains
`_argv_realpaths()`, and `TestCodexArgv::test_the_exact_argv` compares both
sides through it:

```python
def _argv_realpaths(argv: list) -> list:
    return [
        os.path.realpath(entry) if os.path.isabs(entry) else entry for entry in argv
    ]
```

```python
        assert _argv_realpaths(record["argv"]) == _argv_realpaths(
            [
                str(fake),
                "exec",
                "--model",
                MODEL,
                "--output-schema",
                str(Path(cwd) / CODEX_SCHEMA_NAME),
                ...
```

On macOS `/var` is a symlink to `/private/var`, so `tmp_path` reaches the
per-test directory by one spelling and the child's reported `cwd` by the other;
the two argv lists differed only there. Resolving both sides fixes it without
touching backend behaviour — the backend still passes whatever path it was
given. Only **absolute** entries are resolved, so a flag or a model name is
still compared verbatim and a wrong one reads as itself in the failure output.

**It passes on Linux: `105 passed` for that module, exit 0.** It cannot be run
on macOS from h100, which is why the realpath comparison is shown above
